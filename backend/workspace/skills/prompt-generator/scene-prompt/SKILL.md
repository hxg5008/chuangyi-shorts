# 场景最终提示词（四视图 · 无人物空镜）

生成一张**16:9横向矩形、2×2等大四宫格**场景参考图，**每格也为16:9横向矩形**。前三格是同一空间不同方向的**清晰广角建立镜头（establishing shot）**，右下格是同一空间的90度垂直俯视。四格均为**完全没有人物**的纯场景空镜；保留**前景、中景、后景、出入口、地面、墙面及主要陈设的固定相对位置**，空间结构连续、自洽且可复用。

这张图会作为该场景所有镜头的背景参考锚点：观众和模型都必须能从这张图读懂整个空间的布局——从哪里进出、地面与墙面是什么质感、核心陈设各自固定在什么位置。视角必须稳定、通用。

## 读取与继承

调用 `read_scenes`，参数为 `{}`，按请求中的 `scene_id` 读取目标场景的 `location`、`time`、`prompt`、`lighting` 和 `final_prompt`。不修改场景ID、原场景资料、项目风格或其他资产。

仅改变四宫格排版、指定的四个观察视角及视图标签，不重新设计美术。当前场景资料与用户明确确认的原单图提示词是内容依据。若原单图提示词仍可读取，保留其中有效的场景、照明、色彩、材质、摄影质感与氛围描述，只替换单画面构图及禁止指定标签的冲突文字；不能仅保留物品清单而丢弃原有光影。已被新版本覆盖的提示词，不当作原单图记录。

保持原有光源及方向、色温冷暖、光照强弱、明暗对比、阴影软硬、环境反射、色彩表现、材质质感和自然景深层次。原资料中已经明确的窗格投影、暖光、暗部层次等必须写进最终提示词，不概括成一句“自然光照”。原来没有这些效果时不新增，也不把其他场景一律改成暖金色。

四视图是展示格式，不是新的画风。不得因为使用“参考板”或增加俯视图，将原场景改成平光、统一提亮的展示图、建筑线稿、缩微模型或不同渲染风格。项目原本采用的表现形式继续沿用。各格允许因观察方向而改变可见受光面与遮挡，但不能重新布光或随摄影机移动光源。

画幅固定为16:9横向矩形，2×2等分后每格仍为16:9横向矩形；这项展示要求替代旧提示词中冲突的画幅要求。实际像素尺寸由后端场景图片配置统一传递，生图模型与清晰度沿用当前配置，不向工具传入未声明的尺寸或参考图参数。仅在实际取得原图或其提示词时使用相应内容，不声称已读取未提供的原图。

## 四宫格布局

四格共用同一空间布局与方位基准，在16:9横向图片画布内采用2×2等大排列，每格均为横向矩形；边界简洁，不用大面积边框挤占画面。

- 左上“正向视图”：从主要入口或已确定的主观察方向朝主体空间拍摄，保留该方向的前景框景、主体与纵深关系。已有确认的主视构图与此方向相符时沿用，不为四宫格搬动陈设。
- 右上“45度斜侧视图”：在同一空间内侧移，以相对主视方向约45度观察；展示通道、墙体、门窗与主要陈设的衔接。45度指观察方向，不是歪斜画面。
- 左下“反向视图”：从主视对侧回拍入口方向，呈现真实背向关系，不镜像主视图，不重新设计未见一侧。
- 右下“90度垂直俯视图”：正上方垂直向下展示完整平面布局，家具、门窗、通道和主要功能区与前三格一致。室内仅在显示时隐藏顶盖以看清内部，不改变实际建筑与照明条件，不产生拆顶后新增的天光，不显示成独立摆放的微缩模型。

每格左上角使用黑色半透明底、白色文字，分别逐字标注上述四个中文名称：左上格“正向视图”、右上格“45度斜侧视图”、左下格“反向视图”、右下格“90度垂直俯视图”。标签位置、字号与样式统一，留出边距、清晰可读且不遮挡主体；无论描述使用哪种语言，标签始终保留这四个中文名称，不翻译、不缩写、不添加其他文字。前三格保持原场景的摄影表现与自然层次，俯视格继承相同材质、色调和实际光源。

固定实体的数量、尺度、位置、朝向、材料与新旧状态不变；可见数量随真实遮挡变化。门窗开闭、灯具开关、日夜、天气与场景状态保持一致。不得为补齐四格新增房间、门窗、关键物品或人物。室外场景使用已有道路、建筑或核心实体建立方向，不套入不存在的室内布局。

## 空间结构规则

空间必须**读得懂、对得上、可复用**：

- **前景**：框景/遮挡物（门框、桌角、植物、设备边缘），制造纵深——写出 1-2 个具体元素
- **中景**：场景的主体空间与核心陈设（流水线、床铺、柜台）
- **后景**：空间的延伸（远处的墙、窗、走廊、城市轮廓）
- **出入口**：门、楼梯、通道的位置与样式必须明确（如"画面左侧一扇铁门"），这是后续镜头调度人物进出的依据
- **地面与墙面**：材质、颜色、状态具体化（如"水泥地面有油渍""墙面石灰斑驳"）
- **主要陈设**：写出 2-4 个核心陈设及它们的**固定相对位置**（如"流水线沿墙排开，尽头是吧台"），陈设之间的左右/远近关系要自洽，不要只罗列物品名

## 人物（硬性规则 · 最高优先级）

**场景图中不能出现任何的人，只保留场景本身。**

- 提示词中不描述人物、不提及任何与人物相关的内容
- 场景描述（prompt）中出现的人物信息一律忽略，不写入提示词
- 提示词结尾必须包含："画面中没有任何人物，空场景"

`prompt`（场景描述）中的陈设、年代质感、关键视觉元素必须全部落地；`lighting`（场景光影）要具体化：光源方向、色温冷暖、明暗对比（如"头顶灯管发出冷白光，机器下方投下硬阴影"）。

## 视角与氛围

- 前三格使用稳定的平视或微俯广角，不使用极端俯仰、鱼眼或倾斜构图；右下格按规定使用90度垂直俯视。原有前景框景、空间层次、自然景深及摄影质感不因四宫格而被统一抹平。
- 以 `location` + `time` 确定时间段与光线基调（日/夜/黄昏的光完全不同）
- 氛围词具体化："压抑" → "空气闷热、光线昏暗低沉"，不要只写抽象情绪词
- 描述使用会话语言指令指定的目标语言；仅四个视图标签固定使用指定中文，不要混入无关词汇

## 禁止事项

- 任何人物——**场景图中不能出现任何的人，只保留场景本身**
- 除“正向视图”“45度斜侧视图”“反向视图”“90度垂直俯视图”以外的文字，以及招牌上的可读文字、水印、签名
- 动态模糊、运动中的物体（场景参考图必须静止稳定）
- 只罗列陈设清单而不交代相对位置（空间结构必须连续、自洽）

## 保存

保存前确认：原有场景结构、陈设、材质、时间、光源方向、冷暖、明暗对比、氛围和摄影表现均有对应描述；变化仅为16:9横向四宫格布局、四个观察视角和指定标签。最终提示词使用单段连贯描述，不输出分析、占位符或四份独立提示词。

调用 `save_scene_final_prompt`，仅传 `scene_id` 和 `prompt`，必须实际保存。`prompt` 不重复拼接项目级统一风格前缀，**项目视觉风格由工具自动注入到最终提示词的最前方**。场景自身的具体照明、色彩、材质与摄影表现仍须保留，不得把“不重复项目风格”理解为删除这些内容。
