# 创一剧坊 v4.4 累计更新（2026-11-09）

本次交付在 v4.3 上增加“系统模式与角色资料补齐”，并累计保留 Claude v3.5 后续优化、v4 风格／导入／一体平台接入、即梦共享参考图快照并发修复、v4.2 风格完整详情和 v4.3 角色出现集数。尚未更新前序风格功能的 Windows 源码部署可直接使用本次累计包，无需逐个安装 v4、v4.1、v4.2、v4.3 或 R1／R2 热修。

本轮仅准备更新交付，**没有部署、停止或重启用户生产服务；真实付费模型请求为 0**。最终构建和包校验以随包 `VALIDATION.json` 为准。

## 本次新增

- 项目默认“普通模式”，用户明确开启“系统模式”后，才识别宿主系统、系统界面、具象化身、仅声音和待确认类型。医院系统／系统管理员等词不直接判定为虚拟系统。
- 无实体宿主系统保留原角色 ID、台词与声线，视觉形象使用统一系统界面图；不把它默认画成真人。没有原文可视证据时采用观众界面叠加层，不凭空改动角色知情或情节。
- 界面材质、配色、边框、布局、宿主和呈现方式可编辑；手动保存不调用模型。专用提示词生成与图片生成仍由用户明确操作。
- 旧人像、已采用图、最终提示词和图片历史不删除。类型／设计变化后对不适用的旧图标待核对，明确确认或新图生成后才作为该形态参考。
- 单集、单个角色、批量提资产与批量出图共用类型／完整性服务；未确认类型不默认生成人像，仅声音不送人物出图。
- 角色详情新增“资料检查”：有明确台词而缺声卡时定向补齐；人工非空资料不自动覆盖。普通剧本同样可用这项通用检查。
- 结构化样貌／妆造回填只整理原最终提示词已有设计，并校验逐字证据；旧提示词没有依据时保留缺项，不编造空白人物五官／服装，不重画图片。
- 分镜前检查缺声卡、待确认类型和原文确切系统说话身份的缺登记／关联问题；诊断可定位，原提取历史保留，补齐后另记录同源问题已解决。
- 单集实况覆盖提取与补齐全周期；单集／批次的资料待完善状态不会提前假报全齐，解决后仅消解同源同版本的诊断。
- 分类／补齐轮次持久记录、请求幂等、模型参数冻结、版本核对、重启待核对与显式重试；不自动重发提交结果不明的付费请求。

**规则保护范围：**原 44 份 Skill／系统提示词文件与 22 个受保护工具／主要分镜 Schema 保留原文。本轮并非“程序完全没变”：新增了定向资料补齐模型调用，以及系统模式的独立分类／设计指令、表现上下文、图片适用性和分镜／视频条件校验。新增指令不覆盖原模板；普通模式不进入系统专用分支。详细 API、辅助表、版本、重试与使用步骤见《2026-11-09_系统模式与资料补齐.md》。

导入的规格继续沿用原交付：原文件 6 MB、最多 1000 段、单段 200000 字符；超长段在预览完整保留并要求拆分，不静默截断。事实提取不因项目视觉风格增加艺术修辞。

并发继续沿用原渠道与批次设置：普通中转没有新增隐形的 2／4 个 HTTP 生图限制；原批次每批 1～4 张、默认 3 张及 2 秒提交间隔保留。官号服务的 4 槽与本地图片下载 2 槽是不同阶段。本次系统模式的同身份分类／资料修补防重复不代表把所有文字和图片任务改成全局单并发，也不声称已经实现跨服务器集群调度。

## 现有火宝更新步骤

1. 正常停止原火宝。将整个原程序目录另存；至少保留完整 `data`、实际可编辑 workspace、`backend/.env`、`network.json`，不要删除原目录。
2. 将累计总包解压到单独目录。打开 `01_创一剧坊累计更新`，这一层应能看到 `backend`、`frontend`、`scripts` 等程序目录。
3. 将这一层全部内容复制到旧火宝根目录，选择替换同名**程序文件**；不要把整个 `01_创一剧坊累计更新` 再套一层。例如旧目录可为 `D:\项目\huobao-source-20261107-platform`。
4. 覆盖包不带真实 `data`、`.env`、网络 JSON 或可编辑 workspace，保留现有数据与账号。本轮没有新增 npm 依赖，原依赖可继续使用。
5. 正常启动火宝，浏览器 Ctrl＋F5。通过 `/api/v1/health` 和随包收据核对为本次 v4.4 健康标识，不凭文件夹名称判断运行版本。
6. 普通项目先检查原页面与资料读取；有系统的项目再明确开启系统模式。先查看类型与原文依据，确认旧图适用性后再少量真实验收。

本轮功能需要同时更新前后端，不建议仅替换一个 Vue 文件。辅助表由新程序初始化，现有项目、账号和 Cookie 不需要重新迁移或重新导入。

## 配套一体平台

本轮系统模式／角色资料改动位于火宝侧。已使用一体执行平台 **1.2.0** 的机器可保留现有平台程序，只更新火宝。累计包内的平台覆盖目录继续使用已核验的 1.2.0 程序，不宣称平台因本次系统功能再次改版。

从较早平台更新时，先正常停止并备份整套平台。将 `02_一体执行平台累计更新` 内程序内容覆盖原平台根目录，保留完整 `data` 和 `网络设置.json`；不要重复迁移、重新导入 Cookie 或登录 GPT。项目原账号、画布、原任务路由与 Key 继续保留。

平台管理网页仍是受信管理入口，面向创作者公开的是火宝登录页；此包没有把平台管理网页改造成多用户公网管理门户。

## 验证、限制与回退

本轮 domain/API 13 项、系统设置／表现类型 UI 5 项、资料检查 UI 8 项、真实父 SFC 编译／handler 运行 7 项、资料补齐服务 20 项、提取生命周期 4 项及资料诊断显示／编译 3 项专项通过，后端类型检查通过。系统渲染和批次专项，以及最终全量测试、构建、包 SHA、排除项和私有文件扫描，**全量收据见 `VALIDATION.json`**。不要将上述局部数字相加后当成全量总数。

本轮没有读取生产账号、提交真实模型或操作现网服务。自动化用临时数据库与本地 HTTP mock；没有把它描述为真实模型效果、实际即梦成片或逐屏浏览器视觉验收。上线后由使用者按自己的配置做小范围验收。

`@房契` 等名称没有对应绑定图，仍是独立的数据／引用校验问题。系统模式不会自动补造资产、偷偷删掉原引用或替换参考图。

回退前正常停止服务，并另存升级后新产生的项目、任务、图像和表现设置；恢复同一备份时点的程序、数据库和配置。本轮 v4.3 源码备份位于外层 `deployments/System_Mode_20261109_151007`，它不包含用户服务器生产数据备份。原 v4／v4.1／v4.2／v4.3 发布包及原 SHA 保留，不覆盖旧发布记录。
