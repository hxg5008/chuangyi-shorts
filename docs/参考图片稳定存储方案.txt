创一剧坊工作台：参考图片稳定存储方案
更新时间：2026-11-03

推荐方案
阿里云 OSS 私有 Bucket，程序上传参考图，并在每次提交视频任务前生成新的 HTTPS 下载签名。
工作台和数据库继续部署在当前电脑；只把生成视频需要的图片存入 OSS。
当前尚未开通、配置或接入 OSS。本文件是接入方案，不代表已经修复历史临时链接。

为什么需要
当前 seedance2.0-933-c5-fast 接口要求参考图使用公网可访问的 URL。
本机 /static 图片可在工作台显示，但模型平台不能访问 localhost。
上游图片平台给出的临时链接会过期；原图在本机仍然存在，临时链接过期不需要重新画图。
已实测一张旧参考图返回 HTTP 403，签名到期时间早于这批视频的提交时间。

接入后的流程（待实现）
1. 读取本地原图，计算 SHA-256；用 refs/<hash>.<ext> 作为对象名。
2. 在本地保存图片哈希和 OSS 对象名的对应记录。同一图片首次上传后复用对象，避免每次上传。
3. 每次提交视频前重新生成 HTTPS GET 签名链接，按参考图原顺序填入 images。
4. 对新链接做小范围 GET 检查；确认可读取图片后，才提交视频。
5. 默认链接有效期 24 小时；临时身份凭证的有效期更短时，以凭证到期时间为上限，并留出余量。
6. 链接不足以覆盖排队和生成窗口时，先刷新签名，再提交。签名失败时明确提示，不重复提交视频。
7. 本地原图仍保留用于预览和备份。已经提交的任务只查询原 task_id，避免重复扣费。

需要准备的信息
在自己的阿里云账号创建 OSS Bucket：标准存储、私有访问、外网 HTTPS Endpoint。
地域按实际访问条件选定；不承诺某个地域一定能被模型平台访问，接入时需要实测。
需要提供到本机配置的字段：Bucket 名、Region、Endpoint、AccessKey ID、AccessKey Secret（或可续期的 STS 凭证）。
密钥应直接填入本地配置，不发在聊天里，不写入前端页面或公开仓库。
使用单独的 RAM 身份，只授予该 Bucket 的 refs/ 前缀所需的 oss:PutObject 和 oss:GetObject 权限。
程序采用本地哈希记录去重，不依赖全 Bucket 的列表或删除权限。

存储设置
整个 Bucket 保持私有；通过短期签名允许模型读取指定图片。
先用 OSS 提供的 HTTPS 域名即可，不要求先购买自定义域名或开放本地工作台。
关闭防盗链 Referer 限制，或确保允许无 Referer 请求；签名本身承担访问控制。
不要对 refs/ 配置会清理进行中任务参考图的生命周期规则。
费用主要由存储量、请求量和图片下载流量构成，按实际区域及阿里云账单计费，不预估固定金额。

接入验收
先用已有本地图片上传和签名，不重新生成图片。
验证新签名 GET 返回图片、签名刷新后仍指向同一对象、相同图片不重复上传、顺序不变。
验证过期或不可读取的链接在视频提交前被拦截，密钥与完整签名不出现在诊断日志中。
最后选择一条短视频任务做端到端验收；这一项会消耗视频平台额度，需在存储实际配置完成后执行。

本次已经处理与仍待处理的边界
已经增加临时链接过期/即将到期检查、参考图读取诊断，以及提交失败和查询受阻的区分。
这些检查能提前说明失败原因，但不能把过期链接自动续期。
OSS 上传、对象映射、签名刷新及本地配置界面尚待接入；没有存储账号信息时，无法完成公网图片交付验收。
