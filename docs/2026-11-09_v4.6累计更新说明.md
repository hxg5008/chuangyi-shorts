# 创一剧坊 v4.6 累计更新（2026-11-09）

本次在 v4.5 上修复系统模式的分类失败扩大与普通人物连带待确认问题，保留 v4.4 系统模式／资料补齐、v4.5 空白系统底图与本镜界面文字，以及更早的全部累计交付能力。现有部署可使用累计更新包，不需要逐个安装前序热修。

本轮没有部署、停止或重启用户生产服务，没有使用真实账号、Cookie、Key、作品或付费模型。全量测试、构建、原文保护、排除项和包 SHA 以随包外层 `VALIDATION.json` 为准。

## 本次修复

- 分类按角色保存成功结果，单项格式／证据错误不再把整批普通人物一并变成待确认。
- 普通人物恢复需要明确原文和对应实体人物外观／行为依据，不能仅凭姓名、字段非空或名字中没有“系统”猜测。证据矛盾或不足的身份仍保留待确认，人工确认不覆盖。
- 分类模型整体异常保留为识别运行诊断，不给每个人都复制一条错误，也不作为全体身份的结论。
- 共享资料补齐不再因另一候选失败提前退出；已确认普通人物继续补明确需要且缺失的声卡、有据整理原最终提示词中的样貌／妆造。
- 待确认身份不被默认赋予真人设计或声卡，原资料保留；readiness 显示“类型待确认”，不再误称形象资料“不适用”。
- 图片批次只跳过真实待确认角色，正常人物、场景和道具继续；记录对应 ID、原因和数量，实况／看板不全绿假报。
- 图片的局部类型问题保留独立诊断，批次显示需关注；正常成功图片不自动重跑。
- 用户明确“确认后再次补齐”才触发待确认分类的显式重试，已确认普通人不重复分类；同 UUID 重放不重复调用，不能换参数复用旧 UUID。
- 单个角色操作将该真实 ID 限定为本次目标，不顺带重识别未选中的其他待确认身份；批量不传单人范围时仍按本集候选处理。

旧图片批次当时跳过了待确认项，历史警示如实保留。之后确认类型不代表图片已经生成；用户在单项页面明确生成或建立新批次处理缺图，程序不自动重写旧批次或重新消费。

详细根因、使用边界、诊断与维护位置见《2026-11-09_系统识别局部恢复.md》。用户服务器上方的“图片准备失败”等提示尚未逐项从服务器日志核实，本说明不把所有准备错误都归因于本次分类缺口。

| 系统模式 | 普通默认、明确开启系统、人物／界面／化身／仅声音／待确认，保留原身份、台词和声线 |
| 系统底图 | 只作可跨集复用的空白皮肤，设计模型不接收本集语音／剧情，旧图保留但需核对，无 OCR 或自动擦字 |

原 44 份 Skill／系统提示词文件、20 个 Agent 工具输入 Schema 与 2 个主要分镜 Schema 保留原文。本轮改变的是系统身份恢复、共享异常范围、局部派发和诊断，不替换原人物／场景／道具提取规则或原分镜结构，也不调整原渠道／批次并发上限。

## 更新与回退

1. 正常停止原火宝，另存完整程序目录，保留 `data`、实际可编辑 workspace、`backend/.env` 与网络配置。
2. 将累计包内同时包含 `backend`、`frontend`、`scripts` 的火宝程序层覆盖旧根目录，替换程序文件，保留现有数据；不要把外层包目录再套一层，不重新迁移账号。
3. 前后端一并更新，本轮没有新增 npm 依赖。启动后 Ctrl＋F5，通过 `/api/v1/health` 与随包收据核对版本。
4. 普通项目先检查原流程；系统项目核对真实普通人、待确认候选、已有采用图及本镜文字，再明确继续缺项处理。
5. 已使用一体执行平台 1.2.0 的机器可保留当前平台，不因本轮火宝侧类型恢复重复迁移 Cookie 或 GPT 登录资料。

回退前正常停止服务并另存升级后新产生的数据，恢复同一备份时点的程序、数据库与配置。旧发布包、SHA 和历史交付记录保留；代码备份不等于用户服务器生产数据备份。

自动化使用临时数据库与本地 mock，没有真实付费模型或现网验收。最终全量数字及构建结果见 `VALIDATION.json`，不要把不同专项数字相加当作全量统计。真实分类与出图效果、服务器具体准备错误仍需对应日志和小范围真实模型验收。
