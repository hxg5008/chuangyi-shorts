# v4.3.4：即梦账号授权与项目画布选择

配套版本：创一剧坊 `20261110-platform-v4.3.4-production`，一体执行平台 `1.3.0`。本次不改变 Skill、系统提示词、角色提取、分镜拆解、图片与视频提示词正文。

## 管理员先设置

1. 一体执行平台添加并检查即梦账号，保留原 Cookie 和登录目录。
2. 火宝「管理后台 → 一体平台」选择即梦本地协议模型，连接并读取账号，启用项目专属画布并保存连接。
3. 「账号使用权限」为每个账号设置允许使用、全部用户或指定用户，并设置是否允许新建项目画布。管理员自己也在可授权名单中。
4. 需要使用既有画布时，展开「授权已有画布」，明确选择画布和用户。用户不会看到整个共享账号下的全部画布。

同一执行平台地址下的账号授权共用，修改不是只针对某个显示模型名称。保存后的空指定用户名单表示无人获准，不自动变为全部用户。

## 用户在项目中选择

进入某集的「视频制作」，上方显示「即梦账号与画布」。选择获准账号、选择已有授权画布或“新建专用画布”，确认后绑定项目。整部作品的各集共用此项目绑定。

例如张三的项目 A 与李四的项目 B 可以使用同一个即梦账号，但各有独立画布；王五的项目 C 可以用另一个即梦账号。用户无需接触执行平台管理页、Cookie 或访问 Key。

一个画布只能归属一个项目。新建画布使用幂等创建凭据；若响应不确定，继续原操作会核对同一创建结果，不会主动再建一张。平台显示 available 只表示没有本地路由或旧任务占用，并不证明远端绝对空白；既有画布需要管理员确认并授权。

## 切换及批量

切换会保存新的绑定版本。新提交使用新账号／画布，旧视频仍按提交时的账号、画布、路由及专用凭据查询、命名和下载。选择本项目历史画布时可重新采用其已有版本。

批量视频开始时固定绑定 ID 和模型配置，整批各条沿用同一绑定。切换期间正在本地准备或提交、尚未取得接单号的任务会阻止切换。已经交给即梦的任务不需要等出片才允许下一批使用新绑定。

账号权限收回后，禁止新的生成；原已提交任务的查询恢复仍保留原绑定，不自动换到别人的账号。

## 并发

保留一体平台原调度：全局提交并发 1／2／4，按用户公平分配，同账号不同画布可同时提交，同一账号＋同一画布的提交对话保持顺序。完整提交对话结束后释放槽，后续云端生成、查询和下载不占提交槽。

本次没有自动调高用户设置，也不承诺上游同时渲染数量。增加账号不等于增加本地总提交上限；需要在一体平台调整提交并发。

## 兼容与升级

- 未启用项目隔离的旧即梦配置保留原路径，只在后端明确返回 legacy 时使用，不以网络或鉴权错误为降级条件。
- 旧 1.2 平台上的 ready 项目绑定继续可用；新账号／画布选择需更新到 1.3.0。
- 更新前正常停止并备份火宝、一体平台完整数据和网络配置。
- 火宝用 v4.3.4 累计覆盖包覆盖程序根目录，保留 data、backend/workspace、.env、network.json、node_modules。
- 一体平台用 1.3.0 program-update 覆盖程序根目录，保留 data、网络设置.json、runtime、node_modules；不重新迁移账号。
- 更新两端后启动并 Ctrl＋F5。本次未自动部署用户远程服务器。

绑定表升级会保留旧数字 ID、密钥和历史，但支持多个版本后旧程序不能正确理解 current 标记。需要回退时先备份当前数据，再按升级前备份与新增数据情况处理，不要直接覆盖旧代码继续写入。

## 开发契约

火宝管理员：`GET/PUT /api/v1/admin/execution/services/:configId/account-policies`。

项目：`GET /api/v1/dramas/:id/execution-options?config_id=...`，`POST /api/v1/dramas/:id/execution-route`。后者传 config_id、account_id、mode（new／existing）、可选 canvas_id 和 expected_route_id。

任务接口新增 execution_project_route_id，仅用于即梦视频绑定元数据，不拼入提示词。后端逐次校验项目归属、模型权限及账号授权。

执行平台新增管理只读 `GET /hub/jimeng/accounts/:id/canvases`，返回本地缓存与 available／route_bound／legacy_history。`/health` 增加 `canvas_assignment_status:true`。项目专用 Key 不能枚举账号和其他画布。

## 本轮验证

使用临时数据库、两个测试用户、两个假账号和离线执行服务验证同号多项目、跨号切换、旧路由恢复、拒绝越权、明确授权画布和创建幂等。另验证真实工作台批量请求只读取一次绑定，提示词保持原文。没有登录真实账号或提交付费模型任务。
