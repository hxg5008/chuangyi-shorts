# 系统底图与本镜文字分离（2026-11-09，v4.5）

本文说明 v4.5 对系统模式的窄范围修正，供使用、验收和后续开发交接。它承接《2026-11-09_系统模式与资料补齐.md》。本轮没有部署、停止或重启用户生产服务，没有使用生产账号、Cookie、Key、作品或真实付费模型。

## 1. 本轮修正的具体问题

系统角色的视觉参考图会跨分镜、跨剧集复用。旧实现虽然禁止把系统画成人，但允许将“原文已有”的消息、金额、奖励、任务通知写进界面；专用提示词生成还会收到剧本、分类依据和旧样貌信息。因此，第一集的“奖励到账”可能固化在底图里，被之后所有镜头继续引用。

v4.5 将三份资料明确分开：

| 资料 | 保存什么 | 怎样使用 |
| --- | --- | --- |
| 系统基础图 | 界面外形、材质、配色、边框、布局、空白槽位和无文字抽象图标 | 作为跨集复用的视觉皮肤；不含任何可读文字、字母、数字或本集消息 |
| 系统声线与原台词 | 原人物身份、固定声线和原文说的话 | 按原文发声；说了某句话不等于面板上要显示同一句话 |
| 本镜界面文字 | 本镜原文明示的屏显内容，以及用户对本镜明确填写的显示内容 | 只在当前分镜需要显示界面时呈现，不写回系统基础图 |

例如，“系统：宿主获得五万元奖励”首先是一句台词。原文没有另外说面板显示什么，且用户没有填写本镜显示内容时，不把这句台词自动写成“五万元到账”的界面文字。若原文明示“面板显示：任务完成”，则该镜可以显示这项原文证据，不必再手工重复授权。

## 2. 系统基础图的统一规范

基础图规范标记为 `blank-ui-v1`。所有文字与数值区域留空，只有形状、材质、颜色、边框、布局、槽位和抽象图标。标题区、按钮和数据槽位也不能提前填上“系统”“确认”、奖励名称、金额、等级或通知。

本轮保护覆盖以下入口：

- 单角色生成／重绘系统图片。
- 单集与多集批量出图。
- 已保存的专用提示词和缓存提示词。
- 原始专用提示词、风格拼接后的最终发图提示词。
- 独立生成／重新生成系统专用提示词。
- 系统基础图的参考图片和生成版本快照。

系统界面专用设计模型只接收经过检查的界面设计字段和空白基础图规范，**不再接收当前集原文、分类证据、角色样貌、服装、旧人物最终提示词或旧界面消息**。因此，不会为了设计跨集皮肤而把不同集的语音和奖励内容一起交给设计模型。具象化身仍按原作明确形态设计，普通人物继续原人物流程。

程序拒绝明确要求写入消息／数值／文字的基础图指令，并给出“请放到本镜界面文字”的错误。不会为通过校验而静默删掉用户填写的内容、修改原台词或改成另一条提示词。

## 3. 旧提示词、旧图片怎样处理

本轮不删除或覆盖旧提示词、旧图片、采用记录和历史任务。

- 没有新规范标记的旧界面提示词保留可见，但不直接当作新的空白基础图提示词复用。新请求可以用保留下来的合格材质／配色／边框／布局生成空白皮肤；这不代表旧文本被改写。
- 旧图保留在原图片与历史中。缺少新规范标记的系统图显示需核对，不自动进入新的分镜参考图。
- 用户可以先查看旧图。确认它确实是没有本集文字、奖励和数值的空白通用界面后，再明确确认采用；此操作不调用图片模型。
- 用户不愿继续使用旧图时，可明确生成新底图。生成图片仍会按所选渠道计费。
- 新图片任务快照包含规范标记。旧版本晚到结果即使角色 ID／设计版本相同，也不能自动覆盖新规范对应的采用图。

图像规范标记表示请求使用了当前基础图规范，或用户明确核对过已有图片；**它不是程序对图片中文字做了识别，也不是图像必然没有文字的像素级证明**。本轮没有 OCR、自动擦字或自动修图。

## 4. 自选参考图片与后台恢复

若系统基础图请求携带参考图片，只允许当前已确认、符合当前规范且 URL 与采用图一致的系统底图。未核对的旧图、其他 URL 或可能含动态内容的截图会在生成提交前明确拒绝；不会偷偷删除参考图后继续出图，也不会声称已经识别了图片中的字。

图片准备任务恢复继续遵守“先找原任务锚点”的流程：后台重启只关联已经存在的任务，未自动重新调用提示词模型或重新提交图片。没有原任务锚点的中断准备会保留待处理状态。旧任务的请求内容留在原记录中，但旧规范结果不能因为恢复后有了文件就自动成为当前底图。

## 5. 本镜界面文字的使用方法

在单集视频制作中，选中一个实际绑定 `system_ui` 的分镜，可以在视频提示词附近看到“本镜界面文字”。普通模式和没有绑定系统界面的分镜不显示这个编辑器。

1. 展开“原文依据”，查看本镜原文明示的界面文字。这是只读证据，不是模型按系统台词猜出来的文案。
2. 需要额外明确显示的内容，填写在编辑框，每行一条；最多 8 条，每条最多 120 个 Unicode 字符，不自动截断。
3. 点击“保存本镜文字”。此步骤只保存当前分镜的独立显示设置，不调用模型，不改角色资产、声卡、原台词和已生成视频。
4. 保存后，如需应用到视频制作，必须由用户明确重新生成本镜提示词，再检查新的分镜／视频提示词并提交视频。

**清空并保存只取消用户自定义内容，不删除原文明示的屏显证据。** 如果原文明确写了本镜显示“任务完成”，清空自定义后该原文内容仍属于本镜允许显示的内容。系统只是说“任务完成”而未描述面板显示，则不因此自动获得屏显授权。

保存采用版本核对。原文、分镜内容、系统绑定／表现版本或已有显示设置发生变化时，旧版本保存返回冲突，草稿保留供用户核对；不会把旧授权套到另一个分镜或新的系统身份。活动视频、分镜任务及相关未结束分镜批次也有保存保护。

## 6. 原文屏显与分镜的关系

屏显规范标记为 `explicit-display-v1`。

原文解析区分“说话”和“明确显示动作”，只有明确的界面显示内容进入证据。新分镜记录原文来源归属，避免把其他集、其他镜头的屏显串进当前镜头。没有来源编号的旧分镜按已锁定描述中的明确显示动作与实际原文共同核对，不把一句引号内台词直接当成屏显事实。

最终允许内容是本镜可归属的原文明示显示内容与本镜用户自定义内容的合并去重；不会把整部剧本的消息全部授权到一个分镜。

原来的无片外字幕规则继续存在。系统声音标签不默认变成人物嘴型，也不默认强制弹出完整面板。显示界面时仍遵守当前表现形态、参考图和本镜授权内容；纯声音镜头不会为了说一句台词就自动附加底图或整段文字。

## 7. 已保存视频提示词与历史视频

旧版本产生的宽松系统视频提示词保留原文，不批量重写。新的视频提交会检查本镜屏显授权；不符合当前规则时要求用户核对并明确重新生成提示词，而不是先消费视频额度后再提示。

已经提交的任务、已生成视频及其原请求保持原记录。修改本镜界面文字不会修改已生成视频，不自动重新提交，也不会把旧结果伪装成按新规则生成的结果。

## 8. API 与维护位置

接口前缀为 `/api/v1`，继承原账号、项目隔离和私有数据权限。

| 接口 | 含义 |
| --- | --- |
| `GET /storyboards/:id/system-display` | 读取实际绑定界面、版本、用户文字、原文证据和有效显示内容；不调用模型 |
| `PUT /storyboards/:id/system-display` | 显式提交 `{version,texts:string[]}`；只保存显示元数据，不生成提示词或视频 |
| 角色表现元数据接口 | 返回基础图规范版本和旧图需核对状态；采用旧图需明确确认当前基础图规范 |

主要实现：

- `system-reference-policy.ts`：独立空白基础图规范与明确正向文字指令检查。
- `system-image-prompt.ts`、`generation.ts`：专用设计输入、缓存／最终发图检查、参考图与任务规范快照。
- `system-assets.ts`：规范版本与图片兼容标记；旧文本、原图和历史仍保留。
- `system-display-policy.ts`、`system-display.ts`：原文显示证据、分镜授权、版本及保存保护。
- `SystemShotDisplay.vue`：只读依据与本镜用户明确填写，不触发模型。

本轮新增辅助服务、辅助元数据与接口，**未改写原 44 份 Skill／系统提示词文件、20 个 Agent 工具输入 Schema 和 2 个主要分镜 Schema**。单项、批量和直接视频提交共用新的边界检查，不另外编一套普通人物、场景、道具提取规则。

## 9. 验证与实际效果的边界

自动化使用临时数据库、本地 HTTP mock 和实际 SDK／路由调用，覆盖两集不同系统台词不进入底图设计、手写／生成指令拦截、旧缓存保留但不复用、参考图提交前检查、恢复不重提、旧规范迟到结果拒绝，以及组件只读／显式保存／并发／晚响应保护。

最终全量测试、构建、原文保护核验、包排除项和 SHA 以外层 `VALIDATION.json` 为准，不能把不同专项数量直接相加当作全量结果。

本轮真实付费请求为 **0**，没有实际生成图片后做 OCR 或完整逐屏浏览器视觉验收。真实模型是否完全遵守无字基础图要求、视频中中文文字是否清晰、是否与声音同步，仍需使用者在自己的模型和渠道上做小范围真实验收。自动化能证明程序提交了哪些内容、拒绝了哪些明显冲突，不能保证所有模型每张输出的文字效果。
