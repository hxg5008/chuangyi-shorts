# v4.3.12 分镜预算与相邻组修复

日期：2026-11-16。上个完整包 v4.3.11+R2，本次标识 `20261116-platform-v4.3.12-production`。

## 修改范围

1. 分镜规划不再只检查总秒数。新增预计组数 ±20% 校验；目标=后台实际剧本字数/500*60，理想组数=目标秒数/12。使用未取整理想值求允许区间，再取区间内整数；仅极短文本的区间没有正整数时选最近正整数，其他时长/原文/台词约束仍必须通过。
2. 1153字示例：目标138.36秒，理想11.53组，建议12组，允许10–13组；17组×8秒即使总时长136秒也被拒绝。初次规划、恢复旧草稿和容量重分组均经过同一校验。
3. 草稿区域展示后台预算字数、目标时长、建议及允许组数、当前规划及总秒数，不使用页面编辑器字数重新猜测。
4. 相邻衔接冲突不再只要求后一组迁就前一组。对于明确报告的前组末态矛盾，仅对当前未提交的breakdown草稿开启联合修复：前组末镜及result，后组首镜。后组尚无完整原稿时允许按原规划完整生成后组。
5. 非边界镜头、已有台词原词/说话者/声音类型、时间前缀、时长、原文归属、已有素材绑定和音色资料保持锁定；无法可靠定位的旧稿不扩大修改范围。
6. 两组通过普通完整校验和边界修改范围校验后，同一SQLite事务保存。前后两份原稿与哈希留档；版本变化、取消、错误或越权修改不保存半份结果。
7. 同一相邻边界最多2次持久化尝试，无额外网络自动重试。新后组可能影响其后已完成草稿时，后续组原文保留并标记实际复核；续跑不会跳过这个标记。
8. 草稿有折叠式相邻修复记录，显示最近5条的组号、状态与失败原因。内部原稿快照不传给列表界面。

## 保留项和限制

- 44份workspace中的Skill及系统提示词与修改前SHA256一致；不改变提取资产规则、原剧本或视频提交规则。
- 不自动重跑已有项目，不重生成已交付视频，不启动/重启服务器，不操作上游真实账号。
- 动作语义由模型依据原文判断。程序严格检查版本、允许修改范围、原词与结构，不声称机械证明所有剧情逻辑正确。
- 不调整现有中英文统计口径或自动删除双语译文；双语配音策略、旁白/no_dialogue冲突仍需根据实际任务进一步确认。
- Gemini/OpenAI Chat多轮工具thought_signature问题不属于本修复，仍未修复。
