# 创一剧坊 v4.3.3：用户删除、默认模型与宽屏模型编辑

版本标识：`20261110-platform-v4.3.3-production`。基于 v4.3.2 累计更新，保留统一后台、请求日志、风格详情、出现集数、选集、参考图重绘、图片历史及原制作流程。一体执行平台仍为 1.2.0，本次不需要更新它。

## 管理员操作

### 删除用户

进入「管理后台 → 用户与权限」，在目标用户行点击「删除」，阅读确认窗口后点击「删除账号」。

- 账号从正常列表移除，旧会话失效，不能继续登录或提交新任务。
- 保留原用户 ID、项目归属、素材文件、任务及历史请求。管理员仍可查看保留资料；不会把资料转交给同名新账号。
- 再次创建同样用户名会得到新 ID，不继承旧项目或模型授权。
- 当前登录管理员不能删除自己；最后一名有效管理员不能被删除。
- 有实际运行或待派发任务时不允许删除，返回可定位的任务信息。完成或处理任务后再删除，不会替你取消任务或重新调用模型。

### 设置默认模型

进入「管理后台 → 模型渠道」，找到目标模型，点击该行「设为默认」。页面顶部分别显示文字、图片、视频的默认模型。

三种类型互不影响，每种类型只有一个显式默认。模型和渠道必须启用，协议必须可执行。

实际选择顺序：

1. 保留用户已经明确选择的模型，以及已有剧集锁定的图片／视频模型。
2. 尚未选择时，优先使用该用户有权限使用的显式默认模型。
3. 默认不可用或未授权时，按原优先级从该用户可以使用的模型中选择。

修改默认不会给未授权用户开通模型，也不会修改旧剧集或自动发起生成。新建剧集会按当时的默认模型初始化图片／视频配置。

「默认模型」和编辑器中的「默认参数 JSON」不是一回事：前者决定尚未选型号时先选谁，后者决定该模型的尺寸、温度等请求参数。若只希望用户使用一个模型，应仅授权该模型，不能只依靠“默认”限制选择。

### 编辑模型

点击模型行的编辑按钮，打开居中的宽弹窗。头部和保存按钮固定，中间内容独立滚动；窄屏会自适应。

- 基本信息集中展示名称、上游 ID、模型类型和备选优先级。
- 协议改为可搜索列表，右侧显示当前协议详情、真实来源、插件／Provider 标识及已声明能力。
- 同名协议靠来源和 ID 区分。搜索不会自动替换当前选项，保存时仍检查类型与协议匹配。
- 使用权限、能力和默认参数仍保留。没有复制影策的积分定价等未实现功能。

## 开发交接

- `DELETE /api/v1/admin/users/:id`：逻辑删除，保留资料。活动任务返回 HTTP 409、`user_has_active_tasks` 和 `active_tasks`。
- `POST /api/v1/admin/channels/:channelId/models/:modelId/default`：空请求体，成功返回含 `is_default` 的 Binding。
- 复用 `ai_service_configs.is_default`，不新建默认模型表、不重排优先级。
- 用户表启动时增加可空的 `deleted_at`、`deleted_username`；历史日志使用保留用户名，不泄露内部删除占位名。
- 只在隔离数据库中验证删除、同名重建、权限及旧数据保留，未删除真实用户。
- Skill、系统提示词、资产提取及分镜规则保持原文。出图、视频、即梦提交协议未改写。

## 升级

已有同系列版本使用 `chuangyi-platform-v4.3.3-cumulative-update-20261110.zip`：先正常停止火宝并备份整个数据目录，再将包内内容覆盖到程序根目录。不要先删除原目录。

覆盖包不包含 `data/`、`backend/workspace/`、`.env`、`network.json` 或 `node_modules/`，保留账号、作品、历史、自定义 Skill 和网络配置。已有依赖完整的安装无需重新安装依赖。

新电脑使用 `chuangyi-source-20261110-platform-v4.3.3.zip`，先按部署说明安装依赖。此包没有你当前的账号、Key 或作品数据。

启动后按 Ctrl＋F5，`/api/v1/health` 的 release 应为 `20261110-platform-v4.3.3-production`。本地源码已更新和构建，但不会自动覆盖你另一台服务器。

回退应先保存当前全部数据；旧程序不理解逻辑删除标记，不能把覆盖旧代码当成“撤销删除用户”。需要按备份和新增数据状况分别处理，避免退档。
