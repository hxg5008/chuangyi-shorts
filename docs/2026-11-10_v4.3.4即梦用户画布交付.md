# v4.3.4／执行平台 1.3.0：即梦账号与用户画布

本轮实现管理员分配即梦账号、普通用户在自己的项目选择账号／画布、新建项目画布、不可变绑定版本及批量冻结。保持 Skill、系统提示词、分镜、提资产及视频正文处理。升级前程序、私有数据备份和验收证据位于 `deployments/Jimeng_User_Routing_V434_20261110T012342`。

## 使用

管理员在执行平台添加并检查账号，在火宝「管理后台 → 一体平台」保存连接，再按账号勾选可用用户、是否允许新建、哪些已有画布可用。账号权限按服务地址共享，模型权限仍按原渠道授权。管理员自己需要创作时也可在用户名单勾选。

普通用户在「视频制作」上方选择账号与画布，确认后用于该项目所有剧集。两个用户可以同用一个即梦账号，画布独立；同一个用户可在有权限的账号间切换。只显示当前项目和明确授权的画布，不能查看同号下其他人的作品。

切换生成新的绑定，原记录保留。已有任务恢复、命名、下载继续沿原路由；新任务和下一批使用新绑定。整批请求在开始时固定配置 ID 和路由 ID，异步操作中更换默认或切换项目绑定不会串批。

本地未接单任务会阻止切换；已交即梦的云端生成不占提交槽。调度仍是 1／2／4 全局提交槽、按用户公平分配、同画布提交串行。没有自动调大并发或转移失败任务。

## 代码与接口

火宝后端：`services/execution-projects.ts`、新增 `execution-routing-schema.ts`、`routes/execution-projects.ts`。`generation.ts` 和 `routes/tasks.ts` 仅增加路由元数据的类型、校验与透传。普通用户 API 仍有项目及模型权限检查，不返回服务总 Key 或路由私钥。

- 管理：`GET/PUT /api/v1/admin/execution/services/:configId/account-policies`。
- 项目选择：`GET /api/v1/dramas/:id/execution-options?config_id=...`。
- 建立／切换：`POST /api/v1/dramas/:id/execution-route`，传 `config_id/account_id/mode/canvas_id?/expected_route_id`。
- 视频请求：可选正整数 `execution_project_route_id`，仅即梦视频接受。

前端新增 `ProjectExecutionBinding.vue`、`ExecutionAccountPolicies.vue` 和 `utils/execution-binding.js`；在原管理员和视频制作页接入。明确的 legacy 模式继续原路径，网络、权限及暂停错误不会被当作 legacy 绕过。旧 1.2 的 ready 路由可继续，选择入口提示升级。

执行平台新增管理只读 `GET /hub/jimeng/accounts/:id/canvases` 与 `canvas_assignment_status` 能力，基于本地缓存给出 available／route_bound／legacy_history，不触发生成或改变全局画布。返回本地未占用不等于证明远端为空，仍需明确授权。项目 Key 不能访问此列表。

## 数据迁移与升级

火宝旧路由表的 ID、密钥、创建请求编号、自增序列保留，新增 version／is_current／remote_project_id／selection_mode。已有远程 project:N 身份不改，新增版本采用独立远程项目标识。原唯一约束改为版本约束与当前绑定的部分唯一索引。未知扩展表外键存在时拒绝自动重建，不级联删除。

使用累计更新总包内两份目录分别覆盖火宝与执行平台；不要删除原文件夹或 data。执行平台更新包不包含 runtime、node_modules 或网络配置，沿用现有运行时与账号。新安装用完整源码＋完整执行平台包；已有 1.2 的账号无须再迁移。

绑定版本结构不能由旧程序安全解释。回退前先保护新增数据，按升级前备份和当前状态单独处理；不要仅覆盖旧代码继续写新结构。
