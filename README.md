## 使用方式

工作台负责项目、剧本、资产、分镜和成片制作；执行平台负责GPT官号及即梦原生执行。文字、图片、视频模型由管理员在模型渠道配置。普通用户只使用获准的功能和自己的项目。

即梦管理页保留服务连接和“谁可以使用即梦”。保存全功能权限后，获准用户在项目视频页选择已登录账号、使用未分配旧画布、新建画布或改名。旧的逐账号/逐画布授权及高级绑定维护不再作为日常管理入口。已有其他项目归属的画布保持隔离。

切换画布只影响后续任务，已提交及固定路由的排队任务继续使用原账号和画布。接入旧画布不更改旧任务归属，也不重新生成。原画布仍有未完成的本地提交时，会提示等待；已稳定接单的云端生成无需等到最终出片。

## 部署与升级

- 已部署机器：分别覆盖工作台和执行平台程序，保留全部数据与配置，勿先删除旧目录。
- 工作台保留 `data/`、`backend/.env`、`network.json`、`backend/workspace/`。自定义的数据、存储或工作流目录也要整体备份。
- 执行平台保留 `data/`、`网络设置.json`、`runtime/`、`node_modules/`。不用重新迁移账号或导入Cookie。
- 工作台新机从源码安装依赖，按 `部署必读.txt` 和 `首次部署.cmd` 操作；建议使用已验证的Node24 x64。执行平台新机使用完整Windows便携包。
- 从 Git 克隆后，需要自定义监听地址、端口或公网来源时，将 `network.example.json` 复制为 `network.json` 再编辑。
- 先启动执行平台，再启动工作台，浏览器Ctrl+F5。关闭网页不会停止服务。
